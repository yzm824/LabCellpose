LabCellpose 3.0 — Apple Silicon Mac app

Desktop application developer: Zhenmo Yu.
Cellpose and dependencies retain their original authorship and licenses.

Keep the .app intact. You may move it to Applications or another local folder.

THE WINDOW
The window always has the same three panes: the images on the left, the image you are
working on in the middle, and the settings or measurements on the right. The bar at the
top shows the three steps of an analysis: 1 Set up, 2 Review, 3 Export. Click a step to
go to it (also View menu, Command-1, -2, -3). Review and Export become available when an
analysis has finished or saved results are open.

1. SET UP
- Drop a folder, a ZIP or a TIFF on the window (or on the app icon), or click Choose
  images. Images in sub-folders are grouped by folder; a folder is treated as a condition
  in Review and Export. Recent analyses are listed on the start page; click one to reopen it.
- Images (left). Every image is selected after import. Tick the ones to analyse, or use
  Select all / Deselect all and the checkbox of a folder. Click a name to see that image.
- Preview (middle). The buttons above the image show one channel; Shift-click to combine
  channels in colour. Pinch to zoom, drag to pan.
- Channels (right). Name each channel and say what it is. Find cells: Cellpose outlines
  the cells in this channel. Measure: its intensity is measured inside the outlines. At
  least one of each is needed; the line under the Analyze button says what is missing.
- Cell size. Enter the width of a typical cell in pixels, or click Measure on image and
  drag a line across one cell.
- Test on this image. Runs Cellpose on the image in the preview only and draws the
  outlines it finds, with the number of cells and their typical width. Change the cell
  size or the settings and test again until the outlines are right; then analyse
  everything. The first test loads the model (several seconds); later tests are quicker.
  A test saves nothing.
- More settings holds the Cellpose thresholds, the background settings, the width of the
  inner boundary band, the processing device and presets. Presets store channel names,
  roles and settings for images taken with the same protocol, not the images or the
  save location.
- The app remembers the names, roles and settings you last used for images with the same
  number of channels and the same channel metadata, and fills them in next time. A note
  under the channels says so; Start from the defaults undoes it.
- Give the analysis a title, choose where to save it, and click Analyze. Stop keeps what
  was finished. Every analysis creates a new folder; nothing is overwritten.

2. REVIEW
Review opens in the same window when the analysis finishes.
- Images (left). The number beside each image is included / all cells. Click an image to
  go to it. A green tick marks the images you have reviewed, and the bar at the top of the
  list shows how far you are.
- The image (middle). Click a cell to select it. Outlines, Background (the region used as
  background), contrast and the channels shown are display only.
- Cells (below the image). Every cell of this image, or of all images, as a small picture.
  Order them with the cells that deserve a look first (Flagged first), by number, by size
  or by brightness. A dot marks a flagged cell: it touches the image edge, is much smaller
  or larger than the others, or contains saturated pixels. Flags are hints; nothing is
  excluded automatically.
- Measurements (right). The value of the selected cell for the chosen channel and region
  (whole cell, inner boundary band, interior), its raw mean, background and area. The plot
  shows every included cell by condition; click a dot to go to that cell.
- Keyboard. Left/Right (Up/Down) move between cells. X excludes or restores the selected
  cells. Z undoes the last change. Return marks the image as reviewed and goes to the next
  one. [ and ] change image. 1-9 show a channel (Shift to combine). + - 0 zoom; F zooms to
  the cell. O and B switch the outlines and the background region. ? lists all shortcuts.
- Several cells at once. Shift-click or Command-click cells, or Shift-drag a box on the
  image, then press X. Exclude all / Restore all act on every cell of the image; to keep
  only a few cells, exclude all, turn Click to exclude on and click the ones to keep.
- Reason records why a cell is excluded; it is saved with the decision.
- Blind review hides file names and conditions and shows the images in a fixed shuffled
  order, so that decisions are made without knowing the group. The plot then shows one
  group. Switch it off to see the names again; the decisions are the same.
- Every decision is saved at once with the results (qc_review_state.json in the result
  folder). The top right of the window says so, or says what is wrong.
- Summary table and Methods (bottom left) give per-image numbers and the exact methods.

3. EXPORT
- Choose the table: Everything (every region and column, one row per measurement),
  Key values (whole cell: raw mean, background and corrected mean, with image and channel
  names), One row per cell (the key values with the channels side by side), By condition
  (one column per image folder and one row per cell, for a column table in Prism), or
  Custom (your own rows, regions, channels and columns).
- The first rows of the table are shown exactly as they will be saved, with the number of
  rows and columns and the file name. Excluded cells are always left out.
- Save table as CSV writes the file. Review file and other downloads holds the review file
  (to share or archive your decisions, or to load someone else's), the list of excluded
  cells, the original measurements of every cell, and Start a new review.
- The image list stays in view; clicking an image goes back to Review.
- The folder button at the top right shows the result folder in Finder.

Open results (top right of Set up) reopens a completed analysis from any version since
1.2 without analysing again, with its review. Keep the app running while reviewing.

WHAT THE NUMBERS MEAN
Corrected mean = mean of the original pixels inside the outline - the background estimate
for that image and channel. The background is every pixel outside the cells found in the
chosen channel and outside bright signal in the chosen fluorescence channel, with a margin
around both; its median (default) or mean is used, and both are recorded, so the estimate
can be changed in Review without analysing again. Inspect the background region in Review.
Negative values are kept. Whole cell, inner boundary band and interior are geometric
regions; the app does not identify nuclei, Golgi or the plasma membrane biologically.
Display contrast, colours, merged channels and previews never enter a measurement, and
equal display scales do not correct unequal exposure, gain or saturation.

Several channels can be chosen under Find cells. Each is segmented on its own and gives an
independent set of cells; numbers are not matched between them. Review and Export then
offer Cells from to choose the set. The background settings are shared within an image.

Input: aligned 2D grayscale uint8/uint16 TIFF pages, one multi-channel stack per image, in
a folder, a ZIP or a single TIFF. Different channel counts are supported and are offered as
separate groups. Native CZI/ND2/LIF, RGB composites and 3D or time series are not supported;
Z or time stacks must not be treated as channels. Separate per-channel files must first be
combined into registered multi-channel stacks. Settings do not identify stains or cell
types. Re-scan checks the files again after they change; it does not analyse them.

Result folder: measurements.csv and field_summary.csv hold every cell as first analysed;
only the table saved in Export applies your review. CSV rows and mask files use field IDs
such as field_1c415e53bd3bd870; fields.csv lists the image name, folder, source file and
mask files for each ID. Each run also records its configuration, the identity of the
source files, versions, the model hash, validation results and the masks.

Compatibility and status
Apple Silicon (ARM64), macOS 14 or later is the build target. Tested on one Apple Silicon
Mac running macOS 27.0.1, 27.2 and 27.2.1; other Macs and macOS releases are not yet tested.
This is a research pilot, not a validated turnkey assay or an App Store release.
The app has a local ad-hoc signature, not Apple Developer ID notarization.
A downloaded copy may be blocked by macOS. Do not disable system-wide security;
have a trusted developer review/sign/notarize it for broader distribution.

All analysis is local. No lab images, API keys, user settings, or results are
included in this distribution. The large download is the bundled scientific
runtime and Cellpose model, needed for offline execution. The app keeps, on this Mac
only, the list of recent analyses, the settings remembered per image type, the last save
location and the window size.

Application and analysis package: LabCellpose 3.0.
Pinned dependencies: Cellpose 4.2.1.1, cpsam_v2, Python 3.12.14.
The original-pixel intensity calculations, the model weights and the bundled runtime are
unchanged since 2.1: for the same images and settings, the masks and measurement files of
a 3.0 analysis are identical to those of 2.1.
Methods, version locks, license notices and version-specific checksums are
inside LabCellpose.app/Contents/Resources/payload/. Third-party licenses remain
with the corresponding components.

The interface is dark in every step, so that image contrast is judged against the same
surround everywhere. With Reduce Transparency switched on in macOS, overlays are solid;
with Reduce Motion, changes between steps are not animated. The app icon is a static
multi-resolution ICNS asset.

REVIEW FILES AND OLDER VERSIONS
Reviews made with 1.4, 2.0 or 2.1 open in 3.0 with every decision. A review continued in
3.0 still opens in those versions with every decision; they do not show the marks for
reviewed images, and a review changed there comes back without the marks. Decisions
saved by 1.3 in the viewer's browser storage move into the result folder the first time
the run is opened. If the result folder is read-only, decisions are kept for this window
only and the top right of the window says so: save a review file before closing.
A damaged review file blocks changes and export until it is repaired: in Export, under
Review file and other downloads, load a valid review file or start a new review (the old
state is backed up first and can be downloaded). At 50,000 history entries, 10 MB of
review data or the maximum safe revision, further changes are refused without altering
earlier decisions: save the review file and start a new review. Loading the same review
file twice does not duplicate its history. Text in exported tables that resembles a
spreadsheet formula is prefixed with an apostrophe; negative intensities are unchanged.
Tables that contain names with non-English characters start with a UTF-8 byte-order mark
so that Excel reads them. Exported files are named after the analysis title, for example
RY26_HrasCA_vs_HrasDN_included_by_condition.csv.

INPUT AND REVIEW SAFEGUARDS (since 1.3 and 1.4)
A re-scan clears old previews and tests. SHA-256 checks bind inspected TIFF pixels and
metadata (including missing sidecars) to the following preview, test and run. If either
changes, re-scan. Older hand-written CLI configs without digests remain accepted.

Limits are checked before decoding: 32 channels, 16 megapixels per plane (at most
8192 pixels per side), 128 MiB decoded per stack, 256 MiB selected pixels per run,
512 fields per inventory, 2 GiB decoded across an inventory, 256 segmentation tasks,
50,000 objects and 500,000 measurement rows per run. TIFF files/members are limited
to 512 MiB; XML to 8 MiB; ZIPs to 4 GiB and 10,000 entries. ZIP64 is not supported.
Split larger inputs into smaller runs. These ceilings bound work; they do not
guarantee sufficient memory for every image or model operation on every Mac.
Cellpose enlarges each image by 30 / cell diameter before segmentation. A run or test is
refused when the enlarged image would exceed 8192 x 8192 pixels (for 1024-pixel
fields the smallest accepted diameter is 4 px); time and memory still grow quickly
as the diameter gets smaller. Review previews keep up to 1,600 pixels on the longest side
and are reduced automatically for a large batch (down to 384 px) so that the whole review
fits its 128 MiB limit; a run that would need more stops with a clear message (completed
masks are kept). Split such analyses into smaller runs. Measurements always use the
original pixels.

Saved results must be regular files (not symlinks): measurements.csv and run metadata at
most 128 MiB, viewer_data.json at most 384 MiB. Opening saved results rebuilds only the
presentation, in temporary storage, with the current interface; the original files and
the identity of the review are preserved and no inference is repeated. Legacy reports
without viewer data show a notice and the original CSV download; their HTML is kept but
not executed. Only the rebuilt report, the original CSV downloads and the run's review
file are served, on localhost only; saving review state requires the open report's
session token. Quitting the app stops its local server; if the app exits unexpectedly, the
server, a running analysis and a running test stop by themselves. A failed GPU run is
reported, not silently repeated: choose CPU under More settings and start again.
